- (decision) Why: pain+vision — org members need answers grounded in their documents, not generic LLM knowledge; multi-tenant isolation is the security backdrop.
- (capability) CAP-1 Authenticate into a tenant: local User belongs to a Tenant; API issues Bearer JWT with user_id+tenant_id; HTTP builds Actor from verified claims.
- (capability) CAP-2 Upload PDFs to shared tenant corpus: authenticated member adds PDF; document starts pending; other tenants cannot see it. First corpus format PDF only (AD-5).
- (capability) CAP-3 Observe document lifecycle: status pending|processing|ready|failed; HTTP upload leaves pending; worker ProcessDocument is sole writer of processing/ready/failed (AD-4).
- (capability) CAP-4 Ingest PDF into page-aware searchable chunks: extract/chunk/embed/upsert via ports; ready iff points exist for retrieval; failed not retrieved.
- (capability) CAP-5 Retrieve only actor tenant + ready documents: every query filters actor.tenant_id; collection chunks; same embed model for upsert and query (AD-7).
- (capability) CAP-6 Ask grounded questions: assistant message MUST include SourceRef document_id,filename,page,chunk_index; empty retrieval → does not know; do not unground (AD-11).
- (capability) CAP-7 Persist conversations: Conversation has tenant_id+user_id; messages reload for that user in that tenant; assistant sources persist with messages.
- (capability) CAP-8 Delete or replace a document across SQL, S3 key tenant_id/document_id/filename, and all Qdrant points for that document_id (AD-12).
- (capability) CAP-9 Later rag-engineering: hybrid/rerank/query-rewrite behind same retrieve/embed ports and same chunks collection; no second unfiltered index.
- (capability) CAP-10 Later evaluation: jobs via same worker-as-adapter rule; Actor in flat job JSON; Redis+Celery only async fabric.
- (capability) CAP-11 Later production-hardening: RLS, OIDC, observability, managed topology as add-ons; Actor, hexagonal ports, one filtered collection stay.
- (decision) MVP capabilities are CAP-1..CAP-8 (slices identity-and-tenancy through chat). CAP-9..CAP-11 are future/advanced, not first ship.
- (constraint) Tenant isolation is a security boundary. Actor.tenant_id from JWT or job record; never an untrusted client field as the only filter. Cross-tenant retrieval prohibited (AD-2, AD-7, AD-8, AD-4).
- (constraint) Hexagonal layout binding: domain imports none of FastAPI, SQLAlchemy, Celery, Qdrant, LangChain, OpenAI, boto3, web; application imports domain only; web talks HTTP only; no empty layer folders; one vertical slice at a time in stated order (AD-1).
- (constraint) Product execute() and ports are sync; FastAPI product routes are def; SQLAlchemy sync Session. GetReadiness may stay async until rewritten; it is not a template (AD-3).
- (constraint) Worker is an adapter sharing composition root and use cases. Document is the only ingest lifecycle. Job JSON flat tenant_id, user_id, document_id. Redis+Celery is the only async fabric (AD-4).
- (constraint) Thin RAG: extract, chunk, embed, upsert, retrieve, generate are domain ports; LangChain is not the engine; first corpus PDF; one OPENAI_EMBED_MODEL for ingest and query (AD-5, AD-7).
- (constraint) Document bytes behind DocumentBytes S3 adapter; one bucket; key tenant_id/document_id/filename; Garage added with documents slice; prod may point same adapter at Amazon S3 (AD-6).
- (constraint) One Qdrant collection named chunks; Cosine; ingestion creates if missing; deterministic point ids from document_id+chunk_index; payload tenant_id,document_id,filename,page,chunk_index,text (AD-7).
- (constraint) This API issues JWTs for local User rows signed with jwt_secret; web Authorization Bearer; token in memory not localStorage; jobs do not carry JWT (AD-8).
- (constraint) Shared Postgres schema; tenant_id on every tenant-owned table including messages; SQLAlchemy 2.x+Alembic in infrastructure; table documents; statuses pending|processing|ready|failed; RLS not required yet (AD-9).
- (constraint) Domain raises DomainError subclasses; HTTP maps TenantIsolationError 403, NotFoundError 404, other DomainError 409; envelope FastAPI detail string; use cases never take Request/Response (AD-10).
- (constraint) Until a slice adds roles, every tenant member may use every tenant document; retrieval/chat use only ready documents (AD-11).
- (constraint) IDs are UUID strings created in application/domain. Dates UTC ISO-8601 in JSON. Config from env; never commit secrets. Tests with each use case; domain/application tests use in-memory fakes, no Docker. Python type hints; TypeScript strict. Validate untrusted input at HTTP and worker adapters.
- (constraint) Named environment is Docker Compose (postgres, redis, qdrant, api, worker, web; garage added at documents). Cloud/k8s topology is not named for MVP.
- (note) Non-goal: roles/in-tenant ACL in MVP. Non-goal: OIDC/cookies/refresh/revocation in MVP. Non-goal: Postgres RLS in MVP. Non-goal: non-PDF formats in MVP. Non-goal: hybrid/rerank/query-rewrite in MVP. Non-goal: Kafka/domain events. Non-goal: collection-per-tenant, schema-per-tenant, bucket-per-tenant. Non-goal: LangChain as engine. Non-goal: cookie/session auth or localStorage token. Non-goal: async product use cases. Non-goal: API-local disk for document bytes. Non-goal: forwarding JWT to worker. Non-goal: structured logging/tracing as a first-slice requirement (/health and /ready already exist).
- (decision) Success signal: tenant A member uploads PDF, it becomes ready, question is answered with SourceRefs to that PDF; tenant B member cannot list, retrieve, or be answered from tenant A's document.
- (assumption) MVP ship is the loop through chat (CAP-1..CAP-8); rag-engineering, evaluation, and production-hardening are sequenced later per AGENTS.md slice order.
- (assumption) Conversation ownership follows brownfield+ERD: a Conversation belongs to one user_id inside a tenant; threads are not a tenant-wide inbox unless a later slice says so.
- (assumption) Permitted documents for Q&A means all ready documents in the actor's tenant (AD-11), unless a later decision adds an explicit allow-list per question.
- (assumption) Installed lockfile/compose versions remain seed; intended adds (SQLAlchemy, Alembic, qdrant-client, openai, boto3, PyJWT, Garage) land when the owning slice needs them. Version bumps are not product invariants.
- (assumption) Chat generate model id is config OPENAI_CHAT_MODEL at first generate adapter, not a vector-schema decision.
- (question) How are the first Tenant and User records created for local JWT login (seed, invite, self-register)? Architecture only says this API issues JWTs over local User rows.
- (question) What HTTP status is unauthenticated (no/invalid token) vs forbidden (authenticated wrong tenant)? AD-10 names 403/404/409 but not 401.
- (question) Are document size, page count, or concurrent ingest limits in scope for MVP, or unbounded until production-hardening?
- (question) What retrieval k and score/empty policy besides zero hits? Architecture requires I-don't-know on empty retrieval but does not bind k or a low-score cutoff.
- (question) May chat/retrieval accept an optional document_id allow-list per question, or must every question search the whole ready tenant corpus?
- (question) Does re-ingest reuse the same document_id (reset toward pending) or create a new Document? Brownfield mark_processing only from pending, so failed/ready retry needs a named transition.
- (question) What success JSON envelopes and HTTP path prefix should web and API share? Architecture binds error envelope only.
